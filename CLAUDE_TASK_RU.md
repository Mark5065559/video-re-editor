# Задача для Claude Code: аудит и аккуратное завершение VIDEO RE-EDITOR

Ты работаешь внутри уже существующего репозитория VIDEO RE-EDITOR. Не начинай проект заново и не переписывай всё без необходимости. Цель — проверить работоспособность проекта, устранить найденные дефекты и сохранить бесплатный стек.

## Ограничения бюджета и инструментов

- У пользователя осталось примерно 13 USD в неуточнённом балансе/лимите. Относись к этому как к жёсткому лимиту, но не предполагай, что это именно Anthropic API, GitHub Codespaces или баланс хостинга.
- Не вызывай платные API, внешние AI-сервисы, SaaS-монтажёры, платные базы, платное хранилище и не создавай облачные ресурсы.
- Не устанавливай платные зависимости и не предлагай платный тариф как обязательный шаг.
- Сначала выясни по доступной среде, каким способом авторизован Claude Code. Не пытайся включать биллинг, auto-reload или покупать кредиты.
- Используй доступную модель Sonnet для обычных задач. Не переключайся на более дорогую модель без явной необходимости и разрешения пользователя.
- Сначала проведи чтение и аудит, затем сообщи краткий план файлов и команд. Не трать токены на пересказ всего README.
- Работай короткими этапами. После этапа запускай целевые тесты. Не повторяй полный анализ проекта без причины.

## Функциональная цель

Это Telegram-бот для качественной обработки видео, которые пользователь имеет право редактировать. Он не предназначен для сокрытия авторства, обхода Content ID, проверки повторного контента, антиспам-механизмов или иных правил социальных платформ. Не обещай алгоритмический охват.

В проекте используются Python, aiogram 3, FFmpeg/FFprobe и SQLite. Сохраняй эти технологии, если нет доказанной технической причины изменить их.

## Первый этап — только аудит

1. Прочитай `README_RU.md`, `main.py`, `app/` и тесты.
2. Проверь импорты aiogram и корректность внедрения зависимостей в Dispatcher.
3. Проверь FSM: получение видео, выбор пресета, отмена, повторный запуск.
4. Проверь обработку Telegram `video` и `document`, MIME/type checks, лимиты размера, длительности и разрешения.
5. Проверь команды FFmpeg: корректный map для файлов без аудио, все кадрирования, fit/fill, обработку больших файлов и проверку результата.
6. Проверь, что subprocess вызывается без `shell=True`, пользовательские строки не могут попасть в FFmpeg filter expression, а таймауты работают.
7. Проверь удаление временных файлов и то, что SQLite не хранит сами видео.
8. Запусти тесты и `python -m compileall .`.
9. Сообщи найденные проблемы по приоритетам: критичные, важные, косметические.

Пока не вноси изменения. Сначала выведи краткий план исправлений.

## Второй этап — исправления

После согласования плана:

- Исправляй только подтверждённые проблемы.
- Не добавляй платные API и внешние сервисы.
- Не добавляй автоматические скачивания видео с социальных сетей.
- Не добавляй автоматическую публикацию/массовые рассылки.
- Не удаляй исходные файлы до успешной отправки результата.
- Для стандартного Bot API соблюдай лимит скачивания `getFile` до 20 MB и отправки файла до 50 MB. В проекте предусмотрены безопасные настройки 19 MB и 47 MB.
- Режим `local` должен оставаться выключенным по умолчанию. Не включай его, пока не настроен Local Bot API Server.
- Не увеличивай лимиты по умолчанию, чтобы не привести к переполнению диска или памяти.
- Не утверждай, что SHA-256 или небольшие изменения видео делают контент уникальным для алгоритмов.
- Не меняй UX без необходимости.

## Третий этап — тестирование

Запусти:

```bash
python -m compileall .
python -m pytest -q
```

Если FFmpeg установлен, проверь маленький тестовый MP4 (сгенерируй цветовой тестовый ролик локально через lavfi, не загружая его из интернета) в пресетах `reels_fill`, `reels_fit`, `square`, `keep`, `warm`. Проверь, что выходной файл существует, читается ffprobe и имеет ожидаемое соотношение сторон.

Не запускай бота с реальным токеном и не пытайся отправлять сообщения от имени пользователя без его явной команды.
