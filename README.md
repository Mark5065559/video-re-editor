# VIDEO RE-EDITOR — Telegram-бот для обработки видео

Готовый стартовый проект на Python + aiogram + FFmpeg. Бот принимает ролик в Telegram, проверяет его параметры, предлагает варианты кадрирования/формата, создаёт MP4 и возвращает результат. Он также показывает короткие SHA-256 отпечатки до и после обработки и сохраняет историю технических операций в SQLite.

> Это инструмент монтажа и подготовки собственных материалов. Изменение SHA-256 не делает ролик оригинальным, не снимает авторские права и не гарантирует просмотры/рекомендации. Не загружай чужой контент без разрешения.

## Что уже реализовано

- Telegram-интерфейс с меню и inline-кнопками.
- Приём видео и видеофайлов: MP4, MOV, M4V, MKV, WebM, AVI.
- Анализ через FFprobe: длительность, разрешение, наличие аудио, размер.
- Пресеты: Reels 9:16 с кадрированием, Reels 9:16 с сохранением полного кадра, Shorts 9:16, квадрат 1:1, сохранение исходной композиции, мягкая цветокоррекция.
- Перекодирование H.264/AAC через FFmpeg, нормализация громкости, fast-start для MP4.
- Повторное сжатие до 720p, если результат превышает заданный лимит.
- Очередь с ограничением параллельных задач, ограничение частоты запросов, ограничение длительности и размера.
- История операций SQLite, автоматическая очистка временных файлов после обработки и очистка старых временных папок при запуске.
- Docker и запуск в Windows без Docker.

## Важные ограничения Telegram

На дату подготовки комплекта официальный Telegram Bot API позволяет ботам скачивать через `getFile` файлы размером **до 20 MB**. Отправка файла ботом — до **50 MB**. В комплекте по умолчанию установлены безопасные значения: вход 19 MB, выход 47 MB, чтобы не упираться в границу лимита.

Если нужен приём видео больше 20 MB, Telegram предлагает собственный **Local Bot API Server**: локальный сервер может скачивать файлы без ограничения размера и загружать до 2000 MB. Для него нужны `api_id` и `api_hash` с `my.telegram.org`, отдельная установка серверной программы и настройка локального API URL. Это расширенный режим, он не включён автоматически, потому что его развёртывание сложнее и требует больше дискового пространства. Подробности: https://core.telegram.org/bots/api#using-a-local-bot-api-server и https://github.com/tdlib/telegram-bot-api.

Чтобы включить уже предусмотренную поддержку собственного сервера, после корректной установки Local Bot API Server поменяй в `.env`:

```env
BOT_API_MODE=local
BOT_API_BASE_URL=http://127.0.0.1:8081
MAX_INPUT_MB=500
MAX_OUTPUT_MB=1800
```

Эти значения нельзя ставить, пока Local Bot API Server не установлен и не настроен: иначе бот не сможет подключиться. При стандартном сервере оставь `official`, вход 19 MB и выход 47 MB.

## 1. Создай Telegram-бота

1. Открой Telegram и найди официального бота `@BotFather`.
2. Отправь `/newbot`.
3. Введи отображаемое имя, например `Video Re-Editor`.
4. Придумай username, который заканчивается на `bot`, например `my_video_reeditor_bot` (если имя свободно).
5. BotFather выдаст токен. Скопируй его и никому не отправляй. Токен даёт управление ботом.

Если токен случайно попал в публичный репозиторий или чужой чат, немедленно отзови его через BotFather и создай новый.

## 2. Скачай и распакуй ZIP

1. Скачай архив проекта.
2. В Windows нажми по ZIP правой кнопкой → **Извлечь всё**.
3. Перемести папку `video-re-editor` в удобное место, например `C:\Users\ТВОЁ_ИМЯ\Projects\video-re-editor`.
4. Внутри папки найди `.env.example`.
5. Сделай копию этого файла и назови копию `.env` (именно точка в начале, без `.txt`).
6. Открой `.env` Блокнотом и вставь токен после `BOT_TOKEN=`.
7. Оставь `BOT_API_MODE=official` на первом запуске.

**Не загружай `.env` на GitHub.** Файл `.gitignore` уже настроен так, чтобы Git игнорировал `.env`. В репозиторий можно загружать только `.env.example`.

## 3. Создай GitHub-репозиторий

GitHub хранит исходный код. Сам по себе репозиторий не запускает Telegram-бота 24/7.

1. Открой https://github.com/new и войди в свой аккаунт.
2. В поле Repository name напиши `video-re-editor`.
3. Выбери **Private**, чтобы исходники не были видны всем.
4. Не ставь галочки Add README, .gitignore и License — эти файлы уже есть в архиве.
5. Нажми **Create repository**.

### Самый простой способ загрузить файлы

1. Установи GitHub Desktop: https://desktop.github.com/.
2. Открой GitHub Desktop и войди в тот же GitHub-аккаунт.
3. Выбери **File → Add Local Repository**. Укажи распакованную папку `video-re-editor`.
4. Если программа предложит создать репозиторий — выбери создание из существующей папки.
5. Внизу слева в поле Summary напиши `Initial video editor bot`.

7. Нажми **Publish repository** и выбери созданный приватный репозиторий.

Перед публикацией убедись, что `.env` не отображается среди файлов для коммита. Если отображается — остановись и не публикуй. Проверь `.gitignore`.

Альтернатива через PowerShell из папки проекта:

## 4. Запуск бесплатно на своём Windows-компьютере

Это самый предсказуемый вариант без оплаты хостинга. Компьютер должен быть включён, подключён к интернету, а бот — оставаться запущенным. Если закрыть окно или выключить компьютер, бот остановится.

### Подготовка

1. Установи Python 3.12 или новее с https://www.python.org/downloads/windows/. Во время установки обязательно включи **Add python.exe to PATH**.
2. Установи FFmpeg. Для Windows можно использовать инструкцию https://www.gyan.dev/ffmpeg/builds/ или пакетный менеджер `winget install Gyan.FFmpeg`.
3. Открой новое окно PowerShell и проверь:

```powershell
python --version
ffmpeg -version
ffprobe -version
```

Если одна из команд не найдена, перезапусти терминал и проверь установку/PATH.

### Первый запуск

1. Открой папку проекта в Проводнике.
2. Дважды нажми `run_windows.bat`.
3. При первом запуске создастся виртуальное окружение и установятся зависимости.
4. Когда в терминале появится сообщение о запуске бота, открой его Telegram username и нажми `/start`.
5. Отправь тестовое короткое видео размером до 19 MB.

Для остановки нажми `Ctrl+C` в окне, где запущен бот.

## 5. Запуск через Docker (альтернатива)

Установи Docker Desktop для Windows: https://www.docker.com/products/docker-desktop/. Убедись, что Docker Desktop запущен.

Открой PowerShell в папке проекта и выполни:

```powershell
docker compose up -d --build
docker compose logs -f
```

Для остановки:

```powershell
docker compose down
```

Данные SQLite будут храниться в папке `data` рядом с проектом. Не удаляй её, если хочешь сохранить историю.

## 6. Как пользоваться

1. Открой своего бота и отправь `/start`.
2. Нажми «Обработать видео» или просто отправь видео.
3. После анализа выбери нужный пресет.
4. Дождись обработки и получи MP4.
5. Бот покажет параметры, размер и первые 16 символов SHA-256 до/после.

«Заполнить кадр» может обрезать края. «Сохранить весь кадр» не обрезает исходную картинку, но добавляет чёрные поля. Перед публикацией просмотри результат.

## 7. Бесплатный облачный запуск: что важно знать

- **GitHub** — хранилище кода, а не сервер для постоянно работающего бота.
- **GitHub Codespaces** в личном бесплатном аккаунте включает ограниченную месячную квоту вычислений/хранилища (на момент проверки — 120 core-hours и 15 GB-month). Это среда разработки, её не стоит считать бесплатным постоянным хостингом бота. После исчерпания квоты доступ блокируется, если не настроена платная тарификация.
- **Render Free** засыпает после 15 минут без входящего HTTP-трафика, а файловая система эфемерная. Для Telegram-бота на long polling и временных видео это плохое место для надёжной постоянной обработки.
- **Oracle Cloud Always Free** имеет бесплатные ресурсы compute, но требует регистрации, доступность инстансов зависит от региона/ёмкости, и настройка Linux-сервера сложнее. Не считай рекламные пробные кредиты тем же самым, что Always Free; всегда проверяй метку Always Free и лимиты до создания ресурса.
- Условия бесплатных тарифов меняются. Не включай Pay-as-you-go, платные ресурсы, автопополнение или платные API, пока не понимаешь лимиты и возможные списания.

Для первого рабочего запуска я рекомендую локальный Windows-компьютер. Когда бот будет проверен, можно перенести его на бесплатную VM, если аккаунт и ресурсы доступны.

## 8. Как не потратить деньги на Claude при доработке

В проект вложен файл `CLAUDE_TASK_RU.md`. Открой папку в Claude Code и отправь этот файл как задачу. Он просит сначала сделать аудит, а не переписывать всё с нуля.

Чтобы экономить:
- используй Sonnet для обычной проверки/исправлений; не начинай с самой дорогой модели;
- сначала попроси Claude показать план и список файлов, которые он собирается изменить;
- попроси выполнить один этап за раз и не читать повторно весь проект;
- не вставляй в чат содержимое всех файлов — попроси изучить конкретные пути;
- в Claude Code `/cost` показывает расходы текущей сессии при оплате через API; `/status` показывает состояние лимитов плана. Важно понимать, как именно выполнен вход — через подписку или API Console: это разные схемы тарификации;
- проверь Auto-reload / автоматическое пополнение в биллинге Claude Console и отключи его, если не хочешь дополнительных списаний.

Я не вижу твой аккаунт и не могу подтвердить, к какому именно сервису относятся оставшиеся $13. Не вводи платёжные данные и не соглашайся на платное пополнение ради этого проекта.

## 9. Что проект пока не делает

- Не публикует видео в Instagram/TikTok/YouTube автоматически.
- Не обещает просмотры или повышение охватов.
- Не пытается скрывать авторство, обходить Content ID, проверку повторного контента, ограничения и правила платформ.
- Не делает интеллектуальное отслеживание объекта/лица при кадрировании; режим «заполнить кадр» обрезает по центру.
- Не имеет веб-панели и оплаты/подписок.

Это намеренно компактная рабочая первая версия. Её сначала нужно запустить локально и проверить на нескольких собственных роликах.

## 10. Быстрая диагностика

**Бот не отвечает:** проверь, что окно с `main.py` открыто, токен в `.env` верный, и запущена только одна копия бота с этим токеном.

**`Conflict: terminated by other getUpdates request`:** бот запущен одновременно в двух местах. Останови лишний процесс.

**`ffmpeg` или `ffprobe` не найден:** установи FFmpeg и перезапусти PowerShell.

**Файл больше 20 MB:** обычный Bot API не скачает его через `getFile`. Уменьши размер исходника либо отдельно настрой Local Bot API Server.

**Итоговый файл больше 47 MB:** бот один раз попробует экспортировать 720p с более сильным сжатием. Если этого недостаточно — нужен более короткий/меньший исходник.

**Ошибка Telegram при отправке:** проверь, что итоговый файл не превышает выбранный лимит, и посмотри последние строки терминала.
