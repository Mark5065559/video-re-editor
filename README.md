# VIDEO RE-EDITOR — Telegram-бот для обработки и уникализации видео

Python + aiogram 3 + FFmpeg + SQLite. Всё бесплатно: никаких платных API, облачных монтажёров и подписок. Бот принимает ролик в Telegram, проверяет его, предлагает варианты обработки и возвращает готовый MP4.

> Это инструмент монтажа собственных материалов. Используй видео и звук, на которые у тебя есть права. Изменение файла и картинки не снимает авторские права и не гарантирует, как площадки (TikTok, Instagram, YouTube) оценят ролик, — бот ничего не обещает про охваты.

## Что умеет

- **🎲 Уникализатор.** Делает 1, 2, 3 или 5 технически разных копий. В каждой копии свой случайный набор небольших изменений: зум и сдвиг кадра, микро-поворот (без чёрных углов), яркость/контраст/насыщенность/гамма, оттенок, зерно, резкость, виньетка (сильный режим), скорость 1–6 % (звук ускоряется синхронно), обрезка долей секунды с краёв, громкость и эквалайзер, частота дискретизации, новые метаданные (дата создания, без версий FFmpeg и служебной информации x264), разные параметры кодирования. Настройки: интенсивность (лёгкая/средняя/сильная), число копий, зеркало, изменение скорости, формат (исходный, 9:16, 1:1).
- **Пресеты:** Reels 9:16 с кадрированием, Reels 9:16 с сохранением всего кадра, Shorts 9:16, квадрат 1:1, сохранение исходной композиции, мягкая тёплая коррекция. Перекодирование H.264/AAC, нормализация громкости, fast-start.
- **Большие видео — до 2000 МБ** (по умолчанию вход 300 МБ, выход 1000 МБ), если указать бесплатные `TG_API_ID` и `TG_API_HASH` (см. ниже). Без них — стандартный лимит Bot API 20 МБ.
- Принимает видео, файлы-видео (MP4, MOV, M4V, MKV, WebM, AVI, 3GP, MTS, TS, MPG, FLV, WMV), кружочки и GIF-анимации. Правильно понимает вертикальные видео с телефона (поворот в метаданных) и нестандартные пиксели.
- Прогресс обработки и загрузки в процентах, кнопка «⏹ Остановить».
- Исходник хранится 30 минут: можно сделать ещё варианты без повторной загрузки.
- Если обработка не удалась, исходник не удаляется — можно сразу выбрать другой вариант.
- Если результат больше лимита, бот один раз пережимает его с битрейтом, рассчитанным под лимит.
- Доступ: первый, кто напишет боту, становится владельцем, остальные получают отказ — ничего вписывать не нужно. Можно задать список ID (`ALLOWED_USER_IDS`) или сделать бота публичным (`ACCESS_MODE=public`, с ограничением частоты).
- **Сервер 24/7 в один файл:** установщик для бесплатного Oracle Cloud с уже вписанными ключами, автозапуском и автообновлением (см. `HOSTING_NOTES_RU.md`).
- История в SQLite: только технические параметры и контрольные суммы, сами видео не хранятся.

## Быстрый старт на Windows (бесплатно)

1. Установи **Python 3.13** (или 3.12) с https://www.python.org/downloads/windows/ — обязательно включи галочку **Add python.exe to PATH**. Python 3.15 и новее пока не подходят: для него ещё нет готовых пакетов.
2. Установи **FFmpeg**: открой PowerShell и выполни `winget install Gyan.FFmpeg`, затем закрой и снова открой PowerShell. Проверка: `ffmpeg -version`.
3. Скачай проект: на странице репозитория GitHub → **Code → Download ZIP**, распакуй, например, в `C:\Users\ТВОЁ_ИМЯ\Projects\video-re-editor`.
4. В папке проекта скопируй `.env.example` в файл `.env` (точка в начале, без `.txt`) и открой его Блокнотом:
   - `BOT_TOKEN=` — токен от `@BotFather`;
   - `TG_API_ID=` и `TG_API_HASH=` — данные с https://my.telegram.org (нужны для видео больше 20 МБ);
   - `ALLOWED_USER_IDS=` можно не заполнять: первый, кто напишет боту, станет владельцем, остальные получат отказ.
5. Дважды нажми `run_windows.bat`. Первый запуск создаст окружение `.venv` и установит зависимости (нужен интернет). Когда появится строка «Бот запущен», открой бота в Telegram и нажми `/start`.

Для остановки нажми `Ctrl+C` в окне бота. Бот работает, пока окно открыто и компьютер включён.

> Если Блокнот сохранил файл как `.env.txt`, бот подскажет переименовать его. В Проводнике включи «Вид → Расширения имён файлов», чтобы видеть настоящее имя.

## Большие видео: 50, 60, 300 МБ и больше

Официальный HTTP Bot API позволяет ботам скачивать файлы только до **20 МБ** и отправлять до **50 МБ**. Чтобы обойти это бесплатно, бот дополнительно подключается к Telegram по протоколу **MTProto** (библиотека Telethon) — тем же ботом и тем же токеном. Отдельный сервер не нужен.

1. Зайди на https://my.telegram.org с номером своего Telegram → **API development tools**.
2. Создай приложение (название и короткое имя — любые, платформа — Other). Скопируй **App api_id** и **App api_hash**.
3. Впиши их в `.env`:

```env
TG_API_ID=12345678
TG_API_HASH=0123456789abcdef0123456789abcdef
```

4. Перезапусти бота. В окне появится «MTProto подключён», а лимиты станут: вход до 300 МБ, выход до 1000 МБ. Их можно поднять в `.env` (`MAX_INPUT_MB`, `MAX_OUTPUT_MB`, максимум 2000) — только если хватает места на диске и мощности компьютера.

Как это работает: файлы до 20 МБ бот скачивает обычным способом, больше — через MTProto; готовые видео до 49 МБ отправляет обычным способом, больше — через MTProto. Если MTProto не смог подключиться, бот всё равно работает с обычными лимитами и пишет причину в окне.

`api_id`/`api_hash` — данные твоего приложения Telegram, не публикуй их. Сессия MTProto хранится в `data/mtproto_bot_<id>.session` — это тоже секрет, он в `.gitignore`.

Альтернатива для опытных — собственный Local Bot API Server (`BOT_API_MODE=local`). Он сложнее в установке и здесь не нужен.

## Как пользоваться

1. Отправь видео — лучше **как файл** (скрепка → Файл): так Telegram не сжимает его.
2. Бот покажет разрешение, длительность, размер, FPS и наличие звука.
3. Выбери **🎲 Уникализатор** → настрой интенсивность, число копий, зеркало, скорость и формат → **🚀 Запустить**. Или выбери один из пресетов.
4. Получи готовые MP4. В подписи — что изменено и короткие SHA-256 до/после (хеш — просто контрольная сумма, на охваты он не влияет).
5. Можно сразу выбрать ещё вариант для этого же видео или прислать новое.

Команды: `/start` — меню, `/help` — лимиты и помощь, `/cancel` — остановить обработку или удалить исходник, `/id` — твой Telegram ID.

«Зеркало» переворачивает надписи и логотипы — включай, только если в кадре нет текста. «Заполнить кадр» и формат 9:16/1:1 обрезают края. Перед публикацией просматривай результат.

## Где запускать бесплатно

**GitHub только хранит код, он не запускает бота.** Бот должен постоянно работать на каком-то компьютере.

1. **Render (без банковской карты)** — бесплатный облачный хостинг, вход через GitHub. Бот засыпает без дела и просыпается от сообщения в Telegram, на слабом бесплатном сервере сам включает облегчённую обработку (720p). Запуск — по кнопке с файлом `render.yaml`, вводятся только токен и два ключа. Пошагово — в начале `HOSTING_NOTES_RU.md`.
2. **Oracle Cloud Always Free + установщик в один файл** (нужна карта Visa/Mastercard) — мощный бесплатный сервер, бот работает круглосуточно, ноутбук можно выключать. При создании сервера в Oracle выбираешь файл `video-re-editor-oracle-install.sh` — и всё: он сам ставит FFmpeg, Python, бота, автозапуск и автообновление. Ключи уже вписаны в файл. Пошагово — в `HOSTING_NOTES_RU.md`.
3. **Свой компьютер с Windows** — самый простой вариант для проверки (`run_windows.bat`). Минус: бот работает, только пока компьютер включён и окно открыто. Не запускай его одновременно с сервером.
4. Подробнее про Oracle Cloud Always Free — бесплатный Linux-сервер 24/7. По официальной странице Always Free на момент проверки для машин Ampere A1 дают 3000 OCPU-часов и 18 000 ГБ-часов в месяц (это 4 ядра ARM и 24 ГБ памяти) — этого с запасом хватает для FFmpeg. Минусы: при регистрации нужна банковская карта для проверки (с Always Free деньги не списываются), свободных машин в регионе может не быть, а простаивающую машину Oracle может остановить — тогда её просто запускают снова в консоли. Условия меняются: перед созданием проверь метку **Always Free** и не включай платные ресурсы. Пошаговая инструкция — в `HOSTING_NOTES_RU.md`.
3. Не рекомендуются: Render/Koyeb (бесплатные инстансы засыпают и слишком слабые для FFmpeg), Google Cloud e2-micro (1 ГБ памяти и мало бесплатного исходящего трафика — для видео не хватит), GitHub Codespaces/Actions (не для постоянной работы ботов).

## Запуск через Docker (сервер или Windows с Docker Desktop)

```bash
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f
```

Остановка — `docker compose down`. Данные (история, сессия MTProto, временные файлы) лежат в Docker-томе `botdata` и переживают перезапуск. Контейнер перезапускается сам после сбоя или перезагрузки сервера.

## Настройки `.env`

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | токен от `@BotFather` (обязательно) |
| `TG_API_ID`, `TG_API_HASH` | пусто | данные с my.telegram.org, включают большие файлы |
| `ALLOWED_USER_IDS` | пусто | ID через запятую, кому можно пользоваться ботом (важнее `ACCESS_MODE`) |
| `ACCESS_MODE` | owner | `owner` — первый написавший становится владельцем (хранится в `data/owners.json`), `public` — все пользователи |
| `MAX_INPUT_MB` / `MAX_OUTPUT_MB` | авто | 19/47 без API, 300/1000 с API, 500/1800 в local-режиме; максимум 2000 |
| `MAX_DURATION_SECONDS` | 600 | максимальная длительность исходника |
| `MAX_PARALLEL_JOBS` | 1 | сколько видео обрабатывать одновременно |
| `JOB_TIMEOUT_SECONDS` | 900 | ограничение времени на одну обработку |
| `PENDING_TTL_MINUTES` | 30 | сколько хранить исходник для повторной обработки |
| `MAX_UNIQUE_COPIES` | 5 | максимум копий за один запуск уникализатора (до 10) |
| `USER_RATE_LIMIT_COUNT` / `..._WINDOW_SECONDS` | 3 / 600 | лимит загрузок и обработок для публичного бота |
| `BOT_API_MODE` | official | `local` — только с собственным Local Bot API Server |
| `DATA_DIR` | ./data | папка истории, сессии и временных файлов |
| `PORT`, `WEBHOOK_BASE_URL` | пусто | облачный хостинг: порт HTTP-сервера и публичный адрес https (на Render задаются сами) |
| `RUN_MODE` | auto | `auto` — вебхук, если есть порт и адрес, иначе polling; `polling`; `webhook` |
| `KEEP_AWAKE` | busy | в режиме вебхука: `busy` — не засыпать только во время работы, `always` — никогда, `off` |
| `CPU_PROFILE` | auto | `auto` — облегчённая обработка на слабом сервере (меньше 1 ядра или 1,5 ГБ памяти), `normal`, `lite` |

## Безопасность

- Не публикуй `BOT_TOKEN`, `TG_API_HASH` и файлы `*.session`. Файл `.env` и папка `data/` уже в `.gitignore`.
- Если токен попал в чужие руки или в публичный репозиторий — отзови его в `@BotFather` (`/revoke`), впиши новый в `.env` и перезапусти бота.
- По умолчанию ботом пользуется только владелец — первый, кто ему написал. Чтобы сменить владельца, удали файл `data/owners.json` (на сервере `/var/lib/video-re-editor/owners.json`) и перезапусти бота.
- Обработка идёт через FFmpeg без командной оболочки, в фильтры попадают только числа, которые генерирует бот.

## Диагностика

**Бот не отвечает.** Проверь, что окно с ботом открыто, токен в `.env` верный и запущена только одна копия бота.

**`Conflict: terminated by other getUpdates request`.** Бот запущен одновременно в двух местах — останови лишний.

**«Нет связи с https://api.telegram.org».** Нет интернета или Telegram недоступен из этой сети — проверь VPN/прокси.

**`ffmpeg` или `ffprobe` не найден.** Установи FFmpeg (`winget install Gyan.FFmpeg`) и перезапусти окно.

**Файл больше 20 МБ не принимается.** Не заданы `TG_API_ID`/`TG_API_HASH` или MTProto не подключился — причина написана в окне бота при запуске.

**«MTProto не подключился: ApiIdInvalidError».** Неверные `TG_API_ID`/`TG_API_HASH` — скопируй их с my.telegram.org заново.

**Обработка долгая.** Скорость зависит от компьютера. Сильная интенсивность и формат 9:16 медленнее; 5 копий — это 5 полных обработок. Для длинных роликов ставь меньше копий.

**Ошибка установки зависимостей.** Подходят Python 3.10–3.14. Установи 3.13, удали папку `.venv` и запусти `run_windows.bat` заново.

## Что бот намеренно не делает

- Не скачивает видео из соцсетей и не публикует их автоматически, не делает массовых рассылок.
- Не обещает просмотры, рекомендации и прохождение проверок площадок.
- Не отслеживает лицо/объект при кадрировании (обрезка по центру).
- Не имеет веб-панели и платных подписок.

## Обновления на сервере

Сервер, установленный файлом-установщиком, раз в 6 часов проверяет GitHub. Новая версия ставится, только если прошла проверку и бот не занят обработкой; если она не запустилась, возвращается прежняя. Для этого репозиторий должен оставаться публичным.

## Для разработчика

```bash
pip install -r requirements-dev.txt
python -m compileall -q .
python -m pytest -q
```

Тесты генерируют маленькие цветные ролики через FFmpeg (lavfi) локально и проверяют пресеты, уникализатор, сжатие под лимит, таймауты и полный сценарий бота на поддельном сервере Telegram. Тесты с FFmpeg пропускаются, если он не установлен.
