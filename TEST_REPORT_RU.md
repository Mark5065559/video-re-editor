## Найденные и исправленные ошибки исходной версии

Критичные:
- Новое видео или старая кнопка во время обработки удаляли папку работающей задачи; после неё удалялся уже новый исходник.
- Двойное нажатие на пресет запускало две обработки в один и тот же файл.
- При ошибке исходник удалялся, хотя должен сохраняться до успешной отправки.
- Таймаут не останавливал FFmpeg (поток продолжал работать, семафор освобождался раньше времени).

Важные:
- После `loudnorm` звук получался 96 кГц.
- Видео с нечётной шириной падали в пресетах «Сохранить кадр» и «Тёплая коррекция».
- В запасном сжатии терялась тёплая цветокоррекция; само сжатие не рассчитывалось под лимит.
- Вертикальные видео с телефона показывались с перепутанными шириной и высотой.
- Тайм-ауты aiogram (30 с скачивание, 60 с отправка) срывали большие файлы на медленном интернете.
- Вывод FFmpeg читался в кодировке консоли — на Windows русские метаданные могли вызвать ошибку.
- Брошенные загрузки не удалялись до перезапуска; соединения SQLite не закрывались.
- Docker с папкой `./data` на Linux-сервере не мог писать данные (права root).
- Бралась каждая аудиодорожка, а не первая; `/start` с параметром не распознавался.

Косметические: кириллица в `run_windows.bat`, неверный `ChatAction`, неиспользуемые импорты, сообщения об ошибках.

## Что не проверено в этой среде

- Создание сервера в самом Oracle Cloud (нужен аккаунт владельца) и работа systemd на настоящей машине.
- Развёртывание на самом Render (нужен аккаунт владельца) и сборка образа на Debian: репозитории Debian закрыты в среде проверки, поэтому замеры сделаны на образе Ubuntu с тем же кодом и теми же библиотеками.
- Реальная работа с Telegram: из среды проверки `api.telegram.org` и серверы MTProto недоступны. Бот с настоящим токеном здесь не запускался, сообщения не отправлялись. Протокол Telegram заменён поддельным сервером в `test_bot_flow.py`; модуль MTProto проверен на корректную обработку недоступной сети.
- Docker проверен частично. Образ на `python:3.12-slim` собран: все Python-зависимости (включая Telethon и cryptg) устанавливаются, контейнер запускается от пользователя `appuser`, том `botdata` доступен для записи, при отсутствии сети бот выходит с понятной ошибкой. Шаг `apt-get install ffmpeg` в этой среде пропущен (нет доступа к репозиториям Debian), на обычном сервере он выполняется как раньше. Заодно подтверждено, что старая схема с папкой `./data` на Linux падала с `PermissionError: /data/temp`.
- Запуск на Windows — `run_windows.bat` проверен только по содержимому.

Перед постоянным использованием запусти бота по `START_HERE_RU.md` и отправь 2–3 своих ролика, включая один больше 20 МБ.
